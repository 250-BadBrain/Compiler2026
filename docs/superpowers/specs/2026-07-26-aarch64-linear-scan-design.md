# AArch64 全局线性扫描寄存器分配设计

## 范围

为通用 IR→AArch64 路径增加函数内全局寄存器分配。结构化 lowering 保持独立，不参与本分配器。实现覆盖整数、指针和浮点 SSA 值、跨基本块活跃区间、调用点约束、Phi copy 合并、按循环深度加权的 spill 决策，以及只为实际 spill 值分配栈槽。

## 分析

1. 从 `Br`/`CondBr` 终结指令构造 CFG、前驱和后继，并以入口 DFS 得到反向后序。
2. 为参数和每条有结果指令编号线性位置；Phi 的回边来源保守延长到函数末尾。
3. 以支配集合识别回边，反向遍历前驱得到自然循环，累计每个块的循环深度。
4. 活跃区间记录定义位置、最后使用位置、类型、是否跨调用和按 `2^loopDepth` 累计的使用代价。

## 分配

- 非跨调用整数/指针优先使用 caller-saved `x10-x15`；`x9` 保留给现有后端临时值。
- 跨调用整数/指针只使用 callee-saved `x19-x28`；不强行把跨调用值放入 caller-saved，因此无需额外调用点保存恢复。
- 非跨调用浮点值使用 `v18-v31`；`v16-v17` 保留为现有浮点临时寄存器。跨调用浮点值 spill，避免违反 AAPCS64。
- 线性扫描按起点排序，过期区间释放寄存器；寄存器耗尽时比较单位长度 spill cost，保留代价更高的区间。
- Phi 目标优先复用已结束且类型兼容的来源寄存器；同寄存器 copy 不发射指令。

## 后端集成

- `valueOffset_` 对寄存器值保存不占帧空间的哨兵槽，槽到物理寄存器的映射由统一 load/store helper 识别。
- 现有指令发射无需逐个重写：对寄存器槽的 load/store 转换为 `mov`/`fmov`，源目标相同时消除。
- `collectFrame` 只为 spill 和 alloca 分配真实偏移。
- 仅保存本函数实际使用的 `x19-x28`，成对使用 `stp/ldp`；奇数尾项使用 `str/ldr`。
- 调用参数寄存器、`x16` 地址临时寄存器及 `v16-v17` 浮点临时寄存器不进入分配池。

## 正确性与保留

- 测试先要求一个无调用的通用函数把跨基本块 SSA 值保留在寄存器中，旧后端应失败。
- 增加 Phi、调用穿越、指针、浮点和寄存器压力用例；ARM 原生输出必须与期望一致。
- 完成主机全量测试、149 项 ARM 功能回归和三次 60 项性能评估。
- 任一错误回退本轮；正确性通过后，以三遍总体均值决定是否保留性能部分。由于该阶段是明确计划项，若总体噪声内持平但访存和栈帧显著下降，可保留并在总结中明确结构性证据。
